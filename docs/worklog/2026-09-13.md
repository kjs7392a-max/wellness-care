## 9 — 직군 화면 문구 두 가지 (사용자 지적)

### ① 제목 「어떤 일을 하고 계신가요?」 → 「어떤 직군이신가요?」

### ② 「앞으로 목소리와 목·어깨 쪽을 먼저 챙겨 드릴게요」 → 무슨 말인지 모르겠다

- 🚫**무엇을(몸풀기 제안) · 어디를(부위) 둘 다 적는다.** → 「목·어깨·목소리를 **풀어주는 몸풀기를 제안해 드려요.**」
- ★**그 아래에 실제로 받게 될 제안 이름을 예로 붙였다** — 「예 · 「퇴근 전 어깨·목 풀기」」. 설명이 아니라 **결과를 그대로 보여주는 것**이 가장 확실하다. `ROLES[직군].items/low[slot]` 에서 뽑으므로 **화면과 어긋날 수 없고**, PAR-Q+ 「예」면 저강도판 이름으로 자동으로 바뀐다.

실측(세 직군 전부): 교사 「퇴근 전 어깨·목 풀기」 · 행정 「퇴근 전 허리 회복 스트레칭」 · 영양·보건·조리 「퇴근 전 다리 부종 덜어내기」.

### ③ 카드 테두리를 진하게 + 직군마다 다른 색
⚠★**내가 「구분선」을 「고른 카드 안 가로선」으로 잘못 읽었다** — 물어보니 **카드 테두리**였다. 🚫**애매한 지시는 데이터를 보지 말고 물어볼 것**(작업 중 「정지」 지시가 나온 것도 이 오독 때문이다).

## 10 — PAR-Q+ 「예」 개수로 단계를 나눔 (사용자 지적: *"예를 누르든 아니오를 누르든 변화가 없다"*)

### 실측 — 지적이 맞았다. 이유는 「같은 영상」이었다
「예」 유무로 제목·라이브러리 개수·본문은 바뀌고 있었지만, **선생님이 실제로 보는 영상**을 재 보니:

## 11 — 직군 화면에서 「제안해 드려요」를 전부 걷어냄 (사용자 지적)
*"아직 아무것도 안 하고 직군만 선택했는데 스트레칭을 제안한다는 게 말이 안 되잖아"*

### ★★ 지적이 맞다 — 내가 만든 것의 전제가 틀렸다
9건차에서 「고르면 무엇이 달라지는지 그 자리에서 말한다」며 `picked` 한 줄과 **실제 제안 이름 예시**까지 붙였다. 그런데 **그 시점엔 걸음도 기록도 PAR-Q+ 답도 아직 없다.** 직군만 고른 상태에서 「이런 몸풀기를 제안해 드려요 · 예 · 「퇴근 전 어깨·목 풀기」」라고 말하는 것은 **아직 하지 않은 판단을 한 척하는 것**이다. 🚫**「선택의 결과를 보여주자」가 「아직 없는 결과를 지어내자」가 되지 않게 할 것.**

### 한 것
- 고른 카드 안의 **✓ 줄 통째로 삭제**(구분선·배지·`picked`·「예 · 「…」」 전부). 고른 티는 **테두리·배경색**이 낸다(10건차에서 만든 것이라 잃는 것이 없다).
- `RoleContent.picked` **데이터에서도 삭제** — 화면에서 뺐는데 데이터에 남겨 두면 다시 붙는다. 그 줄에만 쓰이던 `accent.text` 도 함께 뺐다(`accent` 는 이제 `{ line }` 뿐).
- 상단 본문 **「쌓이는 피로의 자리가 서로 달라서, 제안하는 내용도 달라집니다. 나중에 바꿀 수 있어요.」를 진하게**(`#6b8c9a` 400 → `#2d5c6e` 600). 카드에서 설명을 걷어냈으므로 **이 한 줄이 설명의 전부**다. ★직군 장에만 적용했다 — 다른 세 장의 본문은 손대지 않았다.
- 🚫 `ROLES` 주석에 **「직군 선택 화면에 제안 문구를 적지 말 것」**을 박아 뒀다.

### 검증

## 12 — 홈 「어제 종합 컨디션」에 주간·월간 칩 (사용자 지시)
*"상세보기를 삭제해주고 주간 기록 보기 / 월간 기록 보기 칩을 만들어서 … 어제 것만 보여주는 게 아니고 전주를 일별로 … 월간 보기는 기록을 눌렀을 때 보여주는 걸"*

### 한 것
- 홈 카드에서 **「상세보기 ›」 삭제**. ★**카드 전체를 누르는 동작도 없앴다** — 칩이 서로 다른 곳으로 가므로 어디를 눌렀는지가 분명해야 한다.
- **「주간 기록 보기」** → 옛 상세보기 화면을 **지난 7일 일별**로. **「월간 기록 보기」** → **홈에 머문 채 시트로**(사용자 2차 지시 *"기록 보기로 가는 게 아니고 내용만 가져오게"* — 처음엔 `tab: "records"` 로 탭을 옮겼었다).
  ★★**시트는 「기록」 탭과 같은 `renderRecords()` 를 부른다** — `inSheet` 인자 하나로 겉껍데기(머리줄·아래 여백·제목 유무)만 갈린다. 🚫같은 월간 화면을 한 번 더 만들지 말 것 — 두 곳이 갈린다. 달 넘기기도 같은 상태(`recMonth`)라 탭·시트가 같은 달을 본다.
- `weekConditions(records, days)` 신설(monthly.ts, 순수·테스트 7). ★**단계 판정을 새로 쓰지 않는다** — `dayBodyLevel`·`dayMindLevel`·`overallLevel` 을 그대로 쓰고, 여기서 하는 일은 「원장 한 줄 → 하루 판정 입력」 변환뿐이다. 테스트가 **하루 규칙과 값이 같은지**를 전 일자에 대해 대조한다.
- 쓰지 않게 된 `axis` 헬퍼(어제 한 장 전용)·import 정리.

### ★★ 화면을 보다가 잡은 것 — 한 화면이 같은 날을 두 가지로 말했다
주간 시트 위 카드는 **「어제 좋음」**, 바로 아래 하루씩 보기는 **「어제 보통」**이었다. **목업 원장이 둘이었다** — 홈·상세는 `YESTERDAY` 상수, 기록장은 `mockRecordsUntil`. 따로 있을 땐 안 보이다가 **한 화면에 나란히 놓으니 드러났다.**
- `mockRecordsUntil` 의 **마지막 줄(어제)을 `YESTERDAY` 로 못박았다**(마음카드 결 → SAM 점수 변환도 `samWeight` 경계와 같은 값으로). 🚫어제 값을 두 곳에 적지 말 것 — 고치려면 `YESTERDAY` 하나만.
- 같은 이유로 **`WEEK_FLOW` 목업 상수를 지웠다** — 흐름 바만 별도 상수를 보고 있어 아래 목록과 다른 주를 말했다. 이제 흐름도 원장에서 뽑는다(어제 칸만 세션 값이 반영된 `dayOverall` 로 덮는다).
- 가드 2건 + ⚠**뮤테이션**: 어제 못박기를 없애면 **2건 실패**, 원복 후 93/93.

### ⚠ 곁다리 — `DayMindInput.pick` 에 「그저 그럼」이 없었다
마음카드 3점(neutral)인 날을 **「기록 없음」으로 적을 뻔했다**. `samWeight` 가 쓰는 낱말 그대로 `"neutral"` 을 넣고 근거 문장도 「그저 그런 결」로. 단계 계산은 그대로(0).

### 검증
tsc 0 · **93/93**(85 → +8) · build · ★실화면: 홈에 칩 2개·「상세보기」 0건 / 주간 시트 = 「주간 기록 · 지난 7일을 하루씩」 + 9/12~9/6 일곱 장 + 날짜마다 신체·마음·근거 / **월간 시트** = 「월간 기록」 머리줄 + 기록 탭과 같은 내용, **탭은 홈에 그대로**(강조 불변)·「나의 기록」 제목은 안 그림·시트 안에서 달 넘기기 동작(9월→8월)·‹ 로 닫으면 홈 / ★**어제가 세 곳에서 모두 「좋음」**(홈 카드·흐름 바·하루씩 첫 줄)이고 흐름 바(화~금 보통)와 하루씩(9/8~9/11 보통)이 일치.

### ▶ 사용자 판단 1건
목업 원장이라 **종합 단계가 대부분 「보통」**으로 나온다(신체·마음은 날마다 다르다 — 조금 지침/보통/좋음/기록 없음). 종합이 「다르면 낮은 쪽」 규칙이라 평평해 보인다. 시연에서 기복을 보여주고 싶으면 목업 생성 규칙을 손봐야 한다.

## 13 — 종합 컨디션 카드: 읽는 칩과 누르는 칩을 갈랐다 (사용자 지시)
