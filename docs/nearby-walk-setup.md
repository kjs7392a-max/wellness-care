# 가까운 산책 장소 검색 설정

서버 환경 변수 `GOOGLE_MAPS_API_KEY`를 설정한다. 로컬 개발은 `.env.local`, 운영은 배포 환경의 비밀 환경 변수에 추가한다. 키는 브라우저에 전달하지 않으며 `NEXT_PUBLIC_` 접두어를 붙이지 않는다.

Google Cloud에서 결제 계정이 연결된 프로젝트의 **Places API (New)** 를 활성화한다. API 키를 이 API로 제한하고 서버 배포 환경에 맞는 키 제한 및 사용량 할당량을 설정한다. 키·좌표·검색 결과를 소스나 로그에 넣지 않는다. 설정 후 서버를 재시작/재배포한다.

오늘의 산책 → 가장 가까운 산책로 찾기 → 브라우저 위치 허용 → 장소 이름·주소·직선거리 표시 → 장소의 Google Maps 링크를 확인한다. 서울·경기·충청 등 행정구역을 고정하지 않는다.

검색은 `park`, `hiking_area` 유형을 현재 위치 반경 5,000m에서 거리순으로 조회하고 첫 유효 결과 한 곳을 표시한다. 반경은 후보 검색 한도이며 5km 코스를 추천한다는 뜻이 아니다. Google에 등록되지 않은 길은 나오지 않을 수 있다. 실제 도보 시간이나 경로를 계산하지 않는다. 1km보다 멀면 가벼운 산책에 멀 수 있다는 안내를 표시한다.

키 미설정은 503, Google 오류는 502, 잘못된 좌표는 400으로 처리한다. 위치 권한 거부·시간 초과·결과 없음에는 다른 지역 결과나 서울 기본 좌표로 대체하지 않는다. 좌표는 POST 본문으로 전달하고 응답·외부 요청 캐시와 위치/결과 영구 저장을 하지 않는다. API 사용량 제한은 Google Cloud 할당량으로 설정한다.

검증: `npm test`, `npx tsc --noEmit --incremental false`. 실제 기기의 위치 및 Google 연동 검증은 API 키 설정 후 수행해야 한다.

공식 문서: https://developers.google.com/maps/documentation/places/web-service/nearby-search

## 무료 사용 한도 차단

이 앱의 산책 검색은 **전체 배포 합산 최근 32일 4,500회**로 제한한다. 달력 월의 28~31일보다 긴 창을 사용해 월 경계·시간대에 따른 조기 초기화를 피한다. 월초에 0으로 리셋하지 않고, 각 예약이 32일 지난 뒤 그 자리가 다시 열린다. Google Nearby Search Pro의 현재 무료 월 5,000회보다 보수적인 한도다.

Google 호출 전 공용 Redis에서 서버 시간으로 횟수를 원자적으로 확보한다. 외부 API 오류·결과 없음·응답 손실도 횟수를 반환하지 않는다. 한도 도달은 429, 카운터 미설정/오류는 503으로 처리하고 Google을 호출하지 않는다. 앱 메모리나 브라우저 저장소로 대체하지 않는다. Redis에는 예약 시각과 무작위 식별자만 저장하며 위치·장소·사용자 정보는 보내지 않는다.

추가 서버 환경 변수:

```dotenv
UPSTASH_REDIS_REST_URL=https://발급받은-엔드포인트.upstash.io
UPSTASH_REDIS_REST_TOKEN=발급받은-쓰기-가능-토큰
```

Upstash Redis REST 호환의 **영구 저장소**를 연결한다. 모든 로컬·Preview·Production 및 같은 Google 결제 계정의 해당 SKU 호출은 같은 카운터를 사용해야 한다. 인스턴스별 DB를 만들거나 카운터 키를 변경/삭제하지 않는다. 자동 만료되는 임시 DB를 사용하지 않는다. DB eviction(메모리 부족 시 임의 키 삭제)은 끄고, 제한 도달 시 자동 유료 업그레이드가 되지 않는 요금제를 사용한다. 저장소 서비스 자체의 요금/무료 한도는 Google과 별도이므로 선택 시 확인한다. 저장소 장애 때는 검색이 중지된다.

**보호 범위:** 이 서버 경로를 통과하는 검색에 한한다. 같은 Google 결제 계정의 다른 앱/프로젝트/키에서 이미 사용한 무료분, API 키 유출에 의한 직접 호출, Google 가격 정책 변경, 카운터 삭제/초기화는 이 코드가 막을 수 없다. 전용 Google Cloud 프로젝트와 해당 API로 제한한 서버 키를 사용하고, 같은 결제 계정의 다른 Nearby Search Pro 사용량이 없는지 확인한다. 이미 사용한 계정이면 최초 카운터를 빈 상태로 시작하지 말고 사용량을 반영한 뒤 연결한다. Google Cloud에서 제공되는 요청 할당량 제한도 함께 설정한다.

검증은 모의 HTTP 응답으로 수행한다. 실제 Redis의 EVAL 동시성 및 Google 연결은 환경 변수 설정 후 별도 확인이 필요하다. 키·토큰은 채팅이나 소스에 넣지 않는다.

참고: https://upstash.com/docs/redis/features/restapi
